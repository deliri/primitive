# Browser-local committed key move

`filestore.BrowserCommittedMoveModule` publishes a narrow browser executor using
Go's embedded source and compiler-owned Primitive Core error identities. The
consumer appends those bytes to its normal generated browser module. IndexedDB
owns the browser transaction; this is native browser execution, not a claim that
browser storage runs through Go filesystem APIs.

`commitGuardedMove` takes custody of one database handle, reads exactly two keys
in one store, and calls synchronous application policy with those observations.
Only accepted policy produces the destination write and source deletion. The
promise settles after native commit or abort and handle close. Application
refusals keep their error; native storage and cleanup causes retain Primitive
Core identities. Undefined and asynchronous policy results are refused. No
history scan, background queue, timer, or product ownership model is introduced.

Go publication proof is retained on Furnace at
`/data/evidence/processed/primitive/2026-10-13/browser-committed-move-go02`:
101 passed, zero failed or skipped across the publication test and compiler-bound
public-door inventory. Changing only the projected contract error identity
produced four passing and two failing events. The first attempt failed before
test execution because its selected build-cache directory was not writable;
it remains in `browser-committed-move-go01`. Corrected source and emitted module
facts are sealed with zero source or reference/manifest/disk mismatches.

These counts prove the Go publication boundary. Native IndexedDB browser proof
and the consumer's account-adoption policy are separate requirements; the
workout-first journey is not complete on these counts alone. The ordinary
filestore package suite and unrelated Primitive packages are outside this
focused execution scope.
