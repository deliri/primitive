# Static S3 sealed-file upload

`UploadS3File(ctx, client, S3FileUpload)` composes Primitive's existing file,
JSON, Signature V4 and exact upload doors. It introduces no AWS client,
credential discovery, environment lookup, profile selection, SSO, role refresh,
multipart session or retry loop.

The operator supplies `CredentialFile` as an absolute path on the executing
machine, together with an explicit positive `CredentialMaximumBytes` whole-file
memory budget. There is no default or inferred AWS secret-length ceiling. The
budget must leave room for one extra byte within Go's signed counter domain.
Keep that file private (mode 0600 or 0400) and outside evidence/archive roots.
One held regular-file descriptor supplies both metadata and bytes; group/other
permission bits refuse. An already oversized file refuses before decoding.
Actual consumption is bounded to the budget plus one byte, so growth after
inspection cannot bypass the budget, and exact-budget input requires real EOF.
Its entire format is one JSON object with exactly two nonempty string fields:

```json
{"access_key_id":"OPERATOR_STATIC_ACCESS_KEY_ID","secret_access_key":"OPERATOR_STATIC_SECRET_ACCESS_KEY"}
```

Unknown fields, duplicate fields, nulls, wrong types, multiple documents,
missing members and incomplete JSON refuse before the source or provider is
used. A session token or profile is unsupported and refuses; known temporary
`ASIA` access keys refuse even when their token is omitted. Access-key IDs use
the documented 16–128 ASCII word-character domain. No secret-key length ceiling
is inferred from Core's unrelated secret-storage type. Owned mutable credential
copies are cleared after signing; Go owns temporary JSON/native allocations.
Requests, credentials, private bearers and error diagnostics are redacted.
Native causes remain available through `errors.Is` and `errors.As`.

The request explicitly names an HTTPS regional S3 service origin, signing
region, general-purpose bucket, exact object key, content type, signing instant,
expiry and existing `objectstore.Policy`. No endpoint, region or timeout default
is invented. Standard `s3`/`s3-fips` and the explicit legacy `s3-<region>` service
origins under the existing AWS DNS domains are accepted; bucket URLs, arbitrary
hosts, paths, queries and nonstandard ports refuse. Authorization, region
availability and endpoint/account agreement remain provider facts.

`S3Bucket` supports dotted general-purpose names. This door uses path-style
addressing; access-point aliases, directory buckets, accelerated endpoints and
other resource kinds are outside this contract. `S3Key` preserves UTF-8 bytes
without filesystem normalization, including repeated slashes, reserved URL
characters and balanced relative elements. AWS's native key limit is 1024 UTF-8
bytes; parent elements cannot exceed preceding non-relative elements.

`Expires` is an integer number of seconds, inclusively 1 through 604800. A
fractional duration refuses rather than rounding. Local target expiry uses the
same whole UTC second published in `X-Amz-Date`; an unpublished fractional
signing second never extends the spending window. Temporal overflow refuses.

`Source` is borrowed, already sealed and known in full. Inspect/reopen it through
the existing owners before calling this door. The function neither closes nor
rewinds it. Existing `UploadS3` binds create-only and CRC32C headers into the
private signature, sends the exact declared extent, checks actually consumed
SHA256/CRC32C, enforces the existing single-PutObject provider limit and performs
one attempt. Every failure returns zero `Transfer`, including an uncertain
remote commit. The caller retains the source and resolves that uncertainty.

A confirmed transfer means exact local consumption and provider HTTP success
under AWS's PUT/checksum contract. It does not mean an independently read-back
object, a mandatory response CRC, a versioned bucket or immutable object version.
No upload-response CRC requirement is added. Use the existing separately
authorized download/readback path when independent remote verification is
required before releasing the source.
